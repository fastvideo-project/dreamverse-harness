# @dv/ui-canvas

English | [中文](README.zh.md)

## Summary

Use this package to give the web application a canvas over a DreamVerse project beside the chat. `CanvasView` draws each node of the project's node list on a surface that pans and zooms, linked by the assets that flowed between them, with stale records marked. A node keeps every version of one shot, image, text, or reference and shows the newest. Double-clicking a node opens a floating editor that shows its versions, reruns a version, adds references, or prefills the chat composer. The canvas is the 画布 / Canvas center view; the `dv-canvas` right-Sidebar tab shows the same canvas.

## Use this package

Mount the plugin in a profile that stacks `dsh-web-app` (which provides the right Sidebar, the locale service, and the client module loader) and `@dv/api` (which serves the project routes the canvas calls and the `canvas` slice of [`@dv/canvas`](../canvas/README.md)). Build the browser bundle first: `pnpm run build` writes `lib/client.js`.

The canvas shows the project's current state only, with no history view. It draws one node for each node of the `canvas` slice, which `@dv/canvas` rebuilds from the records, in creation order and at the slice's position: a node holds the records of one item as its versions, oldest first, and its card shows the newest version. The registered `NodeType` whose `type` is the node's `kind` draws it: the canvas hands the type the node and one version, and the type supplies the title, `meta`, assets, preview, and sizing. A node whose kind has no registered type draws a plain 16:9 card titled with the operation label of its newest version. The node ID is the ID that the node list gives it, the ID of the record that created the node. A node owns the assets that its type names (default: the outputs of its newest version), then the outputs of its earlier versions. A badge that a registered `RecordsInUse` reports for an asset, such as 已裁剪 / Trimmed for a clip that a timeline trims, shows as given on the node of that asset. An asset goes on the canvas as a node of kind `asset`, which `@dv/ui-asset-pool` draws, when the user drops its file or its asset pool tile on the canvas, or sends it in a chat message as an attached image or a `dv:asset/<id>` chip (`@dv/chat-references` places those). Each of these is a step of the history, so History lists it and undo reverts it. The canvas follows the current state when it changes, and its edits become steps of the history at once.

```yaml
- id: dv-ui-canvas
  name: '@dv/ui-canvas'
```

The Host half injects the DSH Workspace registry and, while a Connection service is mounted, registers the authenticated Fetch route `/api/dv/canvas/layout`. The route keeps each project's viewport in `<project folder>/.dreamverse/canvas-layout.json`, where the project folder is the path of the Workspace whose ID is the project ID. `GET ?project=<id>` returns `{viewport}`, with `viewport: null` before the first pan or zoom and when the file is missing or unreadable; `POST {project, viewport}` replaces the viewport, writes the file atomically, and returns the stored layout. A viewport is kept only with finite `x` and `y` and a positive `zoom`. Errors use the body `{error, code}` of every `/api/dv` route: 400 `invalid_params` for a malformed project, 404 `unknown_project` for an ID that names no Workspace and for a write to a folder without `.dreamverse/`, which creates nothing. The viewport is view state: it writes no record, so undo never pans or zooms, and removing a project leaves the file in the folder. Node positions and sizes are project content in the `canvas` slice.

The Host half also registers the agent's tool `dv_canvas_read`, which refuses an agent that another agent started, and two more Fetch routes for it. Each mounted canvas holds `GET /api/dv/canvas/agent?project=<id>&session=<id>` open, one stream per project and chat session in a page, which sends `text/event-stream` frames: `ready` and `read` with `{id, stream}`. Each call finds the project of the agent's chat session, the Workspace whose folder is the session's working directory, and writes a `read` frame on every open stream of that project beside that session; the first canvas that answers with `POST /api/dv/canvas/agent/answer` and `{id, stream, project, cards}` settles the read, and an answer that names an unknown read or a stream that the read was not written to gets 404, and answering draws and stores nothing. When no such stream is open, the call fails at once; Config `answerTimeoutMs` (10000 by default) limits the wait for an answer. The read goes to an open canvas because only the browser knows the default size of each node type.

The browser half provides the client service `dvCanvas` (`DvCanvas` of `@dv/ui-canvas/contract`), whose four registries stay empty until plugin UI halves register into them: `nodeTypes` (`NodeType`, keyed by `type`, the node type key that the host producer registers the kind under), `recordsInUse` (`RecordsInUse`, keyed by `id`), `versionKinds` (`VersionKind` of `@dv/ui-kit/registries.ts`, keyed by `kind`), and `actions` (`NodeAction`, keyed by `id`). A plugin's UI half registers its descriptors inside `ctx.inject(['dvCanvas'], …)` and keeps the disposers; a second descriptor with a held key throws an error that names the holder. The browser half registers the `dv.canvas` Component Factory, which takes the props `projectId`, `session`, and `focus`, reads the registries through its inject `hooks`, and declares three keyed child slots that a node type fills under its `NodeType.type`: `dv.canvas.card` (the card body, with the owner props `CardOwner`: the node, the wire asset of each of its assets, the text scale, and a `CardHost`; without an entry the card shows the type label), `dv.canvas.editor` (the editor body, with the owner props `EditorOwner`, whose `EditorHost` adds the editor's asset picker), and `dv.canvas.picker` (the asset pool inside the asset picker, at key `assets`, with the owner props `PickerOwner`). An editor without an entry shows only its header. It also registers the `dv-canvas` tab type (a page the Sidebar's guide offers as "Video canvas"), the `dvCanvas` locale namespace in Chinese and English, the tab body under its own id `@dv/ui-canvas`, and `CanvasCenter` as the `dv.center.view` entry `canvas` (order 0, labeled with the tab type's label 画布 / Canvas). The center view and the tab body each render a `dv.canvas` occurrence for their project and chat session, so both draw the same cards, editors, and picker. Card and editor bodies draw media through the `dv.media` Factory of `@dv/ui-media`. A `NodeAction` shows on each node for which its `shows` returns true, in `order`: in the editor header and inside the frame of a node whose newest version failed; its `run` receives the node and a `NodeHost`, which has no asset picker.

The UI plugins that fill the canvas are `@dv/ui-asset-pool` (the `asset` node type, its card and editor bodies, and the picker's asset pool), `@dv/ui-text-node` (the `text` node type), `@dv/ui-timeline` (the records that timeline clips use and their trim badges), and `@dv/ui-composer` (the "Ask the agent" action, which prefills the chat composer through the `dv:compose` window event). Each generation UI plugin that `defineGenerationUi` of [`@dv/ui-generation`](../ui-generation/README.md) defines, such as `@dv/ui-shot-render` for the `shot` nodes, registers a node type, its card and editor bodies, and the "Retry" action of a node whose newest version failed. The reference nouns `@dv/ui-character`, `@dv/ui-location`, and `@dv/ui-style` come from `defineReferenceUi` of [`@dv/ui-reference-kit`](../ui-reference-kit/README.md): each registers a node type, its card and editor bodies, a version kind, and the records that its references use. While `dvHistory` of `@dv/ui-history` is loaded, the browser half also registers the History rows of `canvas.node_position`: 移动节点 / Moved “{title}” for a move and 调整大小 / Resized “{title}” for a resize, with the title that the node's card shows, and of `canvas.node_remove`: 从画布移除「{title}」 / Removed “{title}”, with the title that the node's card showed before the removal, drawn from the node that the record's `report.removed` keeps; selecting a row opens the node.

| Gesture | Request |
| --- | --- |
| `host.run` of a card body, an editor body, or an action, such as a reference noun's editor adding or removing a reference | `POST /api/dv/operation` with the body's operation, params, inputs, and intent, completed with the canvas's project, chat session, and `surface: 'canvas'`; a failure shows above the canvas |
| `host.rerun`, such as the send of a shot editor's composer or a failed version's "Retry" | `POST /api/dv/operation` with the request and its `based_on` record, completed the same way; the new record becomes the newest version of the same node, and the canvas waits for it |
| Drop files on the canvas | `POST /api/dv/assets/import` with `surface=canvas` for each file, of any media type, whose `asset.import` also puts the asset on the canvas; once its node appears, one `canvas.node_position` record places it under the pointer, and each further one 32 units right of and below the one before |
| Drop an asset pool tile on the canvas | a tile whose asset has a node moves that node under the pointer with one `canvas.node_position` record; any other asset of the asset pool panel runs `POST /api/dv/operation` with `asset.place` and the asset as input role `asset`, and its new node is placed under the pointer the same way |
| 从画布移除 / Remove from canvas in a node's right-click menu, the trash button in its editor header, or Delete or Backspace on the selected node | `window.confirm` asks first; OK sends `POST /api/dv/operation` with `canvas.node_remove` and `nodes: [<node>]`, and Cancel sends nothing. The node, its edges, its selection, its menu and its editor leave once the state shows the record; a refusal shows above the canvas. The key works only while no editor is open, the asset picker and the media preview are closed, and the key does not go to an input, a textarea, or a contenteditable element |
| "Keep anyway" in the editor of a stale node | `POST /api/dv/stale/accept` for the node's record (`proj.stale_accept` as a step of the history) |
| Drag a node | `POST /api/dv/operation` with `canvas.node_position` and the node's new `x` and `y` when the drag ends, one record per drag; the canvas draws the new position at once and puts the node back when the request is refused |
| Pan or zoom | `POST /api/dv/canvas/layout` with the viewport |
| Drag a corner handle of the selected node | `POST /api/dv/operation` with `canvas.node_position` and the node's new `x`, `y`, `width` and `height` when the drag ends, each size at least the node's `minSize`. A window node takes the width and the height that the pointer asks for, and its body shows more or less of its content; a media node keeps its frame height at width / `ratio` + `fixedHeight`, following the axis that the pointer moved more, and its picture scales with the frame. A west or north corner also moves the node so that the opposite corner stays in place. A press on a handle without movement changes nothing and opens no editor |
| The agent's `dv_canvas_node_position` of `@dv/canvas` | no request from the page: the record changes the `canvas` slice, and every mounted canvas of the project draws the node at its new position when it fetches the state on the next `/dv/events` frame |
| The agent's `dv_canvas_node_remove` of `@dv/canvas` | no request from the page: every mounted canvas of the project drops the node, its edges, and its selection, menu and editor on the next `/dv/events` frame, with no notice; History shows the step |

Every request except the layout requests carries `surface: 'canvas'` and the chat session the canvas sits beside, which the record stores as its `session`. The center view opens a node when the workspace center hands it the request `{ record: <id> }`, which `dvCenter.show({ view: 'canvas', target: { record } })` of `@dv/ui-shell/contract` names, as History does for a selected record. The canvas centers, selects, and opens the node whose ID is that ID, else the node that holds the record as a version, else the node that holds the record's first output. A request waits while no node matches, so a node type that registers later still opens its node; the canvas takes the request when it opens the node, so a remounted canvas does not open the node again. The tab body passes no focus.

The floating editor opens centered over the dimmed canvas, at most 720 px wide and about 80% of the canvas height. Drag its title row to move it; drag its right edge, bottom edge, or bottom-right corner to resize it, or focus the corner handle and press the arrow keys (16 px per press); a double click on the title row puts it back at the centered default. The browser keeps one last position and size for every node in `localStorage` and fits them into the canvas the next time the editor opens. A click on the dimmed canvas or Escape closes the editor; with a second editor open over it, the same gestures close only the top one. The editor grows out of its node when it opens and shrinks back into the node when it closes, while the dimmed layer fades (`@dv/ui-kit/zoom.ts`). Its header shows the type dot and the type label (left out when it equals the title), the title, the actions that show on the node, and close; a stale node shows 已过期 / Stale and "Keep anyway" above the body. A node with more than one version shows the version strip below the header: 版本 / Versions, one thumbnail per version in time order, the shown one outlined, and 第 {i} / {n} 版 / Version {i} of {n}. Selecting a thumbnail shows that version in the editor and leaves the card as it is, because the card always shows the newest version; each version mounts its own body, so a draft of one version never carries over to another.

A click on a node selects it, which draws an accent ring and shows its corner handles; a double click opens its editor. Closing the editor keeps the ring, so the node stays easy to find; a click on empty canvas with no editor open clears it. A right click on a node selects it and opens its menu at the pointer, in the style of the timeline tab menu: the node actions that show on the node, then 从画布移除 / Remove from canvas in the danger color with the ⌫ hint. The menu moves left of or above the pointer when the canvas has no room on the right or below, and closes on a press outside it, on Escape, and on a pan or zoom. After a body or an action calls `host.rerun`, the node's actions are disabled (`NodeView.rerunning`), and inside the failed frame the button of the action that started the rerun reads the type's running words, until the node holds a version that it did not hold before; the editor then closes and the canvas centers and selects the node. When the request returns first, the editor closes then. The `host.rerun` of an editor body (`EditorHost`) rejects with the error of a request that fails before the new version appears. The canvas waits for one rerun at a time, so a later rerun settles the rerun that it replaces, which shows no failure. The body shows the error, and the rerun of an action or a card body (`NodeHost`) shows that error in the canvas notice over any open editor, alike from the editor header and the failed frame. A node whose newest version finished with an output and that the user has not opened in this browser shows an accent dot beside its title until its editor opens. The browser keeps the opened versions per project in `localStorage`; a project opened for the first time in a browser starts with every finished version counted as opened.

The canvas draws every node in one chrome: a caption above a frame. The caption is one small line with the title, the unseen dot, the 已过期 / Stale tag, and the meta in the mono style: v{n} for a node of n versions when n is more than 1, then the type's `meta`. A node with more than one version draws two offset frames behind its frame. The frame is a rounded outline with no fill and no shadow; the selection ring and the keyboard focus outline go around the frame alone. Inside the frame, the type's `dv.canvas.card` body fills the frame and paints its own fill (`CARD_SURFACE` of `@dv/ui-kit/frame.ts` for a card-like body, nothing but the picture for a picture body), with the type's status words (`NodeType.status`, else 运行中… / Running… and 失败 / Failed) over it while the newest version is pending or running, and the badges over its bottom-left corner. A node whose newest version failed keeps its frame height and shows no body: the type's failure words and the actions that show on it on the card surface inside the frame, with the version's error message on hover. A node whose newest version is superseded is dimmed, and a stale node's frame has a danger outline. Each edge meets a node at the middle of its frame and takes the color of its source node's type (`NodeType.color`, which colors nothing else); the edges come from the inputs of the newest version, and the edges of the selected node are drawn on top in the accent color. The `NodeHost` that an editor body and an action receive adds these to `run` and `rerun`: `pickAssets` opens the asset picker, `preview` opens the asset preview of `dvMedia.preview` of `@dv/ui-media` growing out of the opener (nothing opens while no media plugin is loaded), `importFiles`, on an editor body's `EditorHost` only, imports local files one after another as canvas imports, which also put each asset on the canvas, and resolves with their asset IDs in file order (a refused import stops the imports and shows the canvas's error notice), `openNode` opens another node's editor over this one, which keeps its unsaved changes, `setPlaced` puts an asset on the canvas or takes its asset node off, and `close` closes the editor. With `versions: true`, the asset picker shows one section per registered version kind, titled with the kind's `label()`, with the newest version of each item that the editor does not hold, drawn through `dv.media`; below them it shows the `dv.canvas.picker` entry at key `assets`. Clicks pick and unpick items, and "Confirm" hands the picked references over in pick order.

## Understand the implementation

<details>
<summary>Implementation internals — click to expand</summary>

`CanvasView` reads the project's current state and the operations with `useProjectState` and `useOperations` from `@dv/ui-kit/useProject.ts`; `buildCanvasGraph` of `graph.ts` turns them and the registered descriptors into nodes and edges. It walks `canvas.order`, finds the newest version of each node among the records, and asks the node's type for the entry of that version; `atVersion` asks for the entry of an earlier version, which the editor's version strip shows. A node draws one edge per input of its newest version, from the node of the versioned item that an `<id>@<version>` input names when a version kind finds that node (`VersionKind.node(state, id)`), else from the node of the input's asset (the node that owns it, else the nearest record up its producer chain that a node holds). A size is the frame box in canvas units; the caption above the frame is not part of it. The entry's `sizing` declares the node's `defaultSize`, its `minSize`, and its kind: a `window` node shows more or less of its body as its frame changes, and a `media` node, whose picture scales with its frame, also declares `aspectRatio`: `ratio`, the picture's width ÷ height, and `fixedHeight`, the height of the fixed bars outside the picture, so that its frame height is width / `ratio` + `fixedHeight`. A node whose stored `width` or `height` is null takes its type's `defaultSize` at its stored corner. The canvas draws, fits, centers, anchors edges at, and reports to `dv_canvas_read` that box. During a drag or a resize, and from the end of the gesture until the state shows the written position, the canvas draws the gesture's box; a refused write drops it and shows the error in the canvas notice. The state refetches on every `/dv/events` frame, so an asset a chat message places appears without a reload. A failed viewport read or write is ignored.

## Model Experience

### `dv_canvas_read` tool definition and results

#### What the model sees

While the DSH tool registry is mounted, the agent sees the tool `dv_canvas_read`, which has no arguments, with the description below. A call returns one text block with JSON: `project` and `cards`, one per drawn node with `id` (the node ID), `type` (the node's kind), `title`, `versions` (how many versions the node holds), `shown` (the record of the newest version, which the card shows), `x`, `y`, `width`, `height` (the position of the node and the size of its frame, below the caption, with the type's default size where the node list holds none), and `rendering`. With no canvas of the project open beside the conversation, the call fails with `No open canvas shows project <id>. Ask the user to open the canvas of this project, then call dv_canvas_read again; dv_proj_state lists the canvas nodes with their positions.` A call from a subagent fails with `dv_canvas_read serves only the agent of the user's conversation, and another agent started this one. dv_proj_state lists the canvas nodes with their positions.` The records that canvas gestures write, the moves and resizes included, reach the model through the project state and update messages and the tools of [`@dv/project`](../project/README.md); [`@dv/canvas`](../canvas/README.md) owns `dv_canvas_node_position` and the `canvas` field of the project summary.

##### dv_canvas_read description

```markdown
Read the canvas of this project that the user has open: every node with its id, type, title, versions (how many versions it holds) and shown (the record of the version it shows), its box (x and y of the top-left corner of the node; width and height of its frame, which sits below a 20-unit caption, so the node spans y to y + 20 + height; canvas units, y grows downward), and rendering: true while the shown version is still being generated. To redo or change a node's content, pass based_on with the shown id. To move or resize a node, call dv_canvas_node_position. Fails when no canvas of this project is open.
```

#### Token effect

About 160 tokens for the definition, in every request while the tool registry is mounted. A result costs about 55 tokens per card.

#### KV Cache effect

The definition is fixed text in the stable tool section; mounting or removing this package changes the tool list and invalidates the cached prefix from the tool section on. The conversation gets each result after its call.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

- **No new nodes from the canvas** — the registered bodies and actions rerun existing records, change the references of characters, locations, and styles, and place or remove assets; starting a character is left to the chat.
- **A stored size does not follow a later picture** — a resized node keeps the size that its `canvas.node_position` record set, so a media node whose picture changes aspect ratio after a resize, such as a new version of another shape, keeps its earlier frame until the user resizes it again.
- **`dv_canvas_read` needs an open canvas** — the read reports the boxes that a mounted canvas draws, because only the browser knows the default size of each node type; without an open canvas beside the conversation, the agent reads the node list with `dv_proj_state`, whose null sizes it cannot turn into boxes.
- **Whole-graph rebuild** — every project event refetches the state and rebuilds the graph; a long project redraws slowly.
- **State through `@dv/ui-kit` hooks** — `CanvasView` reads the project state, the operations, and the interface language through `useProjectState`, `useOperations`, and `useLanguage` of `@dv/ui-kit` instead of an inject `hooks` source, and the plugin injects a `DvClient` instance into the `dv.canvas` Factory and the tab body instead of plain callbacks ([client rules](../../client/AGENTS.md)). No contract type names `DvClient` or a React hook.

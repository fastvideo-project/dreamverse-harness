# Agent Note: The DreamVerse canvas node list is a host base package rebuilt from the records

Status: implemented

English | [中文](2026-11-08-dv-canvas-node-list.zh.md)

## Problem

The DreamVerse canvas drew one node per record. `buildCanvasGraph` in the browser grouped records by their `based_on` lineage, so every rerun, retry, or edited prompt added a node beside the one it changed, and a long session filled the canvas with near-copies of one shot. The node list existed only in the browser: the host could not say which nodes a project had, the agent could read them only while a canvas was open (`dv_canvas_read`), and its `dv_canvas_move` needed that open canvas to know the nodes. Node positions and sizes lived in `<project folder>/.dreamverse/canvas-layout.json`, outside the records, so Undo could not revert a drag or a resize, History did not list them, and a move by the agent was not a step of the project history.

## Decision

A new host base package, [`@dv/canvas`](../../../../packages/dv/canvas/README.md) (service `dvCanvasNodes`, component key `canvas`), owns the node list. Its `canvas` slice holds `nodes` by node ID, `order`, and `assets` (the node that shows each asset). A node holds `kind`, `name`, `versions` (record IDs, oldest first; the card shows the newest), the placed `asset` of a placement node, and `position` `{x, y, width, height}`, where a null size is the default size of the node's type. A node's ID is the ID of the record that created it; a placement of several assets gives the later nodes `<record>.2`, `<record>.3`.

The reducer (`packages/dv/canvas/src/reducer.ts`) reads the chain up to the current position, oldest first, and applies the first matching rule: (1) a record whose `based_on` is a version of node N becomes N's newest version; (2) a record of an operation that a maker registers creates a node of its kind in the first free row of its column; (3) a finished placement `place` record creates a node per input asset that no node shows; (4) a finished placement `unplace` record deletes the placement's nodes of its input assets; (5) a finished `canvas.node_position` record sets the position fields that it gives; (6) every other record leaves the slice unchanged. Rules 1 and 2 take records in any status, so a failed render stays a version with its Retry action. `based_on` is a core record field, so producers need no canvas field: the editor's prompt edit, Rerun, and Retry pass it, and `OperationSpec.basedOn` of `@dv/project` fills it for `<k>.update` of `@dv/reference-kit` and the writes of `@dv/text-node` when the caller names none.

Producers register with the service inside `ctx.inject(['dvCanvasNodes'], …)`, so each loads without the canvas: `registerMaker({operations, kind, column, makes?})` for `defineGeneration` (`shot`, `image`, `audio`), `defineReference` (`<k>.create`), `@dv/text-node` (`textnode.write`), and `@dv/asset-pool` (`asset.import` with `place: true`); `registerPlacement({place, unplace, kind, column})` for `asset.place` and `asset.unplace`, which `@dv/asset-pool` registers only while the canvas is loaded. Rule R4 of [`scripts/dv-architecture.ts`](../../../../scripts/dv-architecture.ts) lets a host package name only operations of its own key, so `@dv/canvas` reads operation names only from these registrations. The host and the browser agree on one string, the node type key: the producer's `kind` equals the `type` of the UI plugin's `NodeType`, as React Flow keys `nodeTypes`, tldraw keys a `ShapeUtil` per shape type, and Jupyter keys renderers by MIME type. A kind without a registered type draws a plain card.

Moves are records. A drag or a corner resize in [`@dv/ui-canvas`](../../../../packages/dv/ui-canvas/README.md) writes one `canvas.node_position` record when the gesture ends, and `dvProject` turns the operation into the agent tool `dv_canvas_node_position`, which works with no canvas open. History labels these rows 移动节点 / Moved “{title}” and 调整大小 / Resized “{title}” through the optional `HistoryRow.label` of `@dv/ui-history`. The reducer's `agentSummary` adds `canvas` (node, kind, name, shown version, position) to the project summary. `canvas-layout.json` keeps only the viewport, which is view state: Undo does not pan or zoom. `dv_canvas_move` and its `moved` stream frame are deleted; `dv_canvas_read` reports cards keyed by node ID with `versions` and `shown`, because only the browser knows each type's default size. The node list comes only from logged records, and the agent reads it through tools whose results are logged, so the model-visible ⟺ logged rule holds without a new `SessionEventMap` member.

## Alternatives considered

**`@dv/ui-canvas` owns the node list.** The list must update while no canvas is open, for example when the agent renders, so a reducer and an operation must run on the host. `@dv/ui-canvas` is UI core, which value-imports only `@dv/project/grammar` and `@dv/project/folder` of the kernel (`importAllowed`, rule R7 (a) in `scripts/dv-architecture.ts`), so it cannot register a reducer or an operation.

**Keep positions in `canvas-layout.json`.** The file sits outside the records, so Undo, Redo, and History cannot revert or list a move, and the agent's move needs the host half of a UI package to write it. A record per gesture costs one line in `records.jsonl` per drag and puts every move on the history list, which is the behavior the user asked for.

**A `node` argument on the generation tools.** The agent would name the node that a render joins. It lost because `based_on` already links a version to the record it changes, every caller already sets it, and a second link could disagree with it.

**Keep the browser grouping by `based_on` lineage.** `buildCanvasGraph` could draw one node per lineage group. It lost because the grouping drew one node per rerun, the host would still know no node, and neither the agent without a canvas nor Undo could reach the nodes.

## Consequences

**What the design buys.** A rerun, retry, or prompt edit adds a version to the same node; a card shows the newest version with v{n} and offset frames, and the editor's version strip shows the older ones. Every move and resize is a step that Undo reverts and History names. The agent reads the nodes in `dv_proj_state` and moves them with no canvas open.

**What it costs.** The host places a new node by a nominal 240 × 200 cell, because only the browser knows a type's default size, so a tall default card can overlap the node placed in the next row until someone moves it; `canvas.node_position` does not refuse an overlapping position for the same reason. Every drag adds a record. A producer that is not loaded makes no nodes, and the moves of its nodes have no effect until it loads again, because the slice is computed from the records and the loaded registrations at every read. The `NodeType` contract of `@dv/ui-canvas/contract` lost `claimed`, `entries`, `column`, and `deepenOn`, and the `dv.canvas.editor.claimed` slot is deleted, so every node type draws through one `entry(node)` and one editor slot. The node type key of `@dv/ui-shot-render` is `shot` (label 镜头 / Shot) and that of `@dv/ui-text-node` is `text`, to equal the host kinds.

**Verification.** `packages/dv/canvas/tests/reducer.spec.ts` covers each reducer rule, the free-row placement, a rerun of a rerun joining the first node, an undo replay restoring the earlier position, and the summary fields; `packages/dv/canvas/tests/canvas.spec.ts` boots the service through the Loader and covers a rerun in the same node, the nodes leaving with their maker, `dv_canvas_node_position` with no canvas open and its undo, the refusals, and the removal on dispose. The node list stories of `packages/dv/e2e/tests/stories/canvas-timeline.e2e.ts` check one node with two versions, a drag and a resize that Undo reverts, and the agent's move with no canvas open. The dv-architecture gate checks the package layer and rules R3, R4, and R7.

# Agent Note: 提示词媒体引用

Status: proposed

[English](2026-10-15-prompt-media-citations.md) | 中文

## 问题

一次渲染调用接受一个 `prompt` 和一个单独的 `reference` 列表。如果提示词用 MiniMax H3 token 指向每个参考素材，例如 `<Picture 1>` 或 `<Video 1>`，那么这种调用有三个问题：

1. 提示词和 `reference` 列表是两个输入。agent（智能体）可能写出两个不一致的输入。
2. 这些 token 只适用于 MiniMax H3。其他视频模型使用不同的语法。例如，Seedance 使用 `图片1`，Kling 使用 `@<name>`。
3. 阅读提示词的人看不出每个 token 指向哪张图片或哪段视频。

## 提案

每个提示词直接引用媒体。渲染时，harness 和模型插件把每个引用转换为目标模型接受的语法。现有的提示词和项目不需要迁移。

### 归属

每个步骤有一个归属方。harness 解析、提取、展开和检查引用。每个模型插件把展开后的引用转换为其模型的语法。agent 只写引用。

| 步骤                             | 归属方                                                   |
| -------------------------------- | -------------------------------------------------------- |
| 定义引用语法，并在服务端解析引用 | `@dv/models`                                             |
| 从 `@` 菜单插入引用              | `@dv/ui-composer`（对话），`@dv/ui-canvas`（版本编辑器） |
| 在客户端把引用显示为缩略图       | `@dv/ui-kit`                                             |
| 从提示词提取发送列表             | `@dv/shot-render`（`shot.render`）                       |
| 返回待用素材警告和首帧错误       | `@dv/shot-render`（`shot.render`）                       |
| 展开角色引用和场景引用           | `@dv/shot-render`（`shot.render`）                       |
| 渲染前检查分镜计划的所有镜头     | `@dv/shot-plan`（`plan.approve`）                        |
| 声明参考素材的最大数量           | 每个模型插件，例如 `@dv/fastvideo`                       |
| 把引用转换为模型的语法           | 每个模型插件，例如 `@dv/fastvideo`                       |
| 判断被引用的视频是否有声音       | 需要该信息的模型插件，例如 `@dv/fastvideo`               |

`@dv/models` 拥有引用语法，因为引用语法是 harness 发给每个模型插件的 `RenderRequest` 的一部分。在 `RenderRequest` 中，`prompt` 保存展开后的引用，`references` 按首次引用的顺序保存被引用的素材。

### 引用语法

引用使用对话语法 `@[<label>](dv:<target>)`。目标是以下值之一：

| 目标                                    | 引用对象                   |
| --------------------------------------- | -------------------------- |
| `dv:asset/<asset-id>`                   | 一个图片、视频或音频素材。 |
| `dv:first-frame`                        | 该版本的首帧。             |
| `dv:character/<character-id>@<version>` | 一个角色的一个版本。       |
| `dv:location/<location-id>@<version>`   | 一个场景的一个版本。       |

### 发送列表

1. harness 从提示词中的引用提取发送列表。
2. `shot.render` 没有单独的 `reference` 参数。agent 只写提示词。
3. `shot.render` 把它的 `reference` 输入标为 `fromParams`。对每个调用方，`@dv/project` 的运行器都从提示词读取 `reference` 输入。运行器拒绝调用方传入的 `reference` 输入。
4. 分镜计划的镜头在其提示词中使用同样的引用。分镜计划没有单独的参考列表。
5. UI 为每个被引用的素材显示一个缩略图和一个列表条目。

### 参考区

版本的参考区保存被引用的素材和待用素材。待用素材是参考区中提示词没有引用的素材。

1. “添加素材”按钮把素材作为待用素材加入参考区。
2. `@` 菜单先显示参考区的素材。
3. 如果用户删除提示词引用的素材，那么 UI 拒绝这次删除。UI 在提示词中高亮该素材的每个引用。
4. 如果用户从提示词删除一个引用，那么该素材作为待用素材留在参考区。

### 渲染时的待用素材

harness 不替 agent 或用户做决定。必须由人或 agent 做这个决定。

1. 如果参考区有待用素材，那么 `shot.render` 不渲染。`shot.render` 返回一个列出这些待用素材的警告。
2. agent 必须带一个明确的选择再次调用 `shot.render`：发送这些待用素材，或不发送这些待用素材。
3. UI 显示一个有两个按钮的对话框："一起发送"（发送这些待用素材）和"不发送"（不发送这些待用素材）。

### 首帧

1. 版本把首帧保存在 `continue_from` 字段中。
2. 提示词可以用 `@[首帧](dv:first-frame)` 引用首帧。
3. 如果提示词引用 `dv:first-frame`，并且 `continue_from` 为空，那么 harness 在渲染前返回错误。
4. 如果 `continue_from` 有值，并且提示词没有引用首帧，那么 harness 渲染该版本。
5. MiniMax H3 插件把首帧引用转换为下一个 `<Picture N>` token。如果某个模型有首帧输入，那么该模型的插件把首帧放入这个输入，并把首帧引用转换为纯文本。

### 角色和场景

角色是 harness 中供人和 agent 使用的概念。角色是一组有名字的参考图。这组参考图告诉人和 agent：这些图片显示同一个人。场景是一组有名字的参考图，表示一个地方。场景遵循与角色相同的规则。视频模型不知道角色或场景。模型只接收具体的图片和视频。

1. 当用户在 `@` 菜单中选择一个角色时，UI 插入一个角色引用。例如，UI 插入 `@[Jensen](dv:character/c1@1)`。角色引用包含角色版本。
2. 用户可以打开角色的子菜单，并引用该角色的一张图片。
3. 渲染时，harness 把每个角色引用展开为该角色各张图片的引用。harness 保持角色的图片顺序。例如，harness 把 `@[Jensen](dv:character/c1@1)` 替换为 `Jensen (@[Jensen · front](dv:asset/a1) @[Jensen · side](dv:asset/a2))`。
4. harness 执行展开。agent 和模型插件不展开角色。
5. 每个版本保存两个提示词：包含角色引用的源提示词，以及 harness 发给模型插件的展开后提示词。因为每个角色引用包含角色版本，所以之后对角色的修改不会改变更早的版本。
6. `shot.render` 的结果包含展开后提示词。agent 可以看到模型接收的图片。

### 模型插件转换

1. 展开之后，提示词只包含素材引用和首帧引用。
2. 每个模型插件把这些引用转换为其模型的语法。例如，`@dv/fastvideo` 把这些引用转换为 MiniMax H3 token `<Picture N>`、`<Video N>` 和 `<Audio N>`。
3. MiniMax H3 为视频的声音分配单独的 `<Audio N>` token。`Asset` 类型不记录声音。因此，MiniMax H3 插件必须在服务端检查每个被引用的视频，判断该视频是否有声音。

### 参考数量上限

1. 每个模型插件声明其模型接受的参考图最大数量。
2. 如果展开后提示词引用的图片多于这个最大数量，那么 `shot.render` 不渲染。`shot.render` 返回警告。agent 或用户决定如何修改提示词。

### 分镜计划批准

`plan.approve` 为已批准的分镜计划的每个镜头调用 `shot.render`。

1. 在渲染任何镜头之前，`plan.approve` 检查分镜计划中的所有镜头。
2. 如果一个或多个镜头有警告或错误，那么 `plan.approve` 不渲染任何镜头。
3. `plan.approve` 一起返回所有镜头的警告和错误。

### 交付

七个 PR（Pull Request）交付本提案。之后的每个 PR 只依赖第一个 PR。

1. 贯穿所有层的图片引用：引用语法和解析器、发送列表、分镜计划的镜头、MiniMax H3 到 `<Picture N>` 的转换、工具描述和技能，以及版本编辑器和分镜计划视图中的引用缩略图。
2. 参考区：待用素材、被拒绝的删除，以及待用素材警告。
3. 首帧：`dv:first-frame`。
4. 角色和场景：展开、角色和场景的版本，以及每个版本的展开后提示词。
5. 视频引用：`<Video N>`。
6. 音频：声音检查和 `<Audio N>`。
7. 渲染前对分镜计划所有镜头的检查。

## 考虑过的替代方案

**单独的参考列表。** agent 写提示词和 `reference` 列表。这两个输入可能不一致。提示词是发送列表的唯一来源，所以 agent 不会犯这个错误。

**自动发送待用素材。** 大多数视频产品发送参考栏中的所有素材，不论素材是否被引用。Cursor 2.0 有一个缺陷：它发送了用户已经移除的附件。harness 不替 agent 或用户做这个决定，所以 harness 返回警告。

**允许带警告地删除被引用的素材。** IntelliJ Safe Delete 先警告，然后删除。这种删除会留下没有目标的引用。UI 拒绝这次删除，并显示每个引用。

**提示词中的模型 token。** `<Picture N>` 是 MiniMax H3 语法。Seedance、Wan 和 Kling 使用不同的语法。当参考素材的顺序改变时，位置 token 的编号也会静默改变。

**角色只用单图引用。** 用户每次都打开角色子菜单，并选择一张图片。我们考察过的产品都不这样做。Kling、Vidu、Google Flow、Luma 和 Krea 为一组图片插入一个引用。Krea 还在渲染时把这组图片展开为其中的各张图片。

**由 agent 展开。** agent 必须找到每个角色的图片。这增加了一个可能的错误来源。提示词也会丢失"这些图片属于同一个角色"这一信息。

**由每个模型插件展开。** 每个插件都必须了解角色，但角色是 harness 的概念。每个插件还会重复相同的代码。

**数量超过上限时保留前几张图片。** Krea 按图片顺序保留前几张图片。这种做法静默移除图片，因此它替 agent 或用户做了决定。

**渲染没有警告的镜头。** 分镜计划会停留在部分渲染的状态。如果对一个镜头的修改引起分镜计划的修改，那么已渲染的镜头就被浪费了。

## 验收标准

1. `shot.render` 没有 `reference` 参数。harness 从提示词提取发送列表。
2. 对于引用一张图片的提示词，`@dv/fastvideo` 发送 `<Picture 1>` 和这张图片。
3. 参考区中有待用素材的提示词返回警告，并且不渲染。
4. 引用 `dv:first-frame` 而 `continue_from` 字段为空的提示词在渲染前返回错误。
5. 角色引用展开为该角色版本的图片。渲染出的版本保存源提示词和展开后提示词。
6. 引用的图片多于模型最大数量的展开后提示词返回警告，并且不渲染。
7. 当一个或多个镜头有警告或错误时，`plan.approve` 不渲染任何镜头。

## 风险

1. 移除 `reference` 参数会改变 agent 的工具契约。使用 `<Picture N>` token 的提示词在这项变更之后不再有效。
2. harness 决定展开后角色的文本格式。某些模型遵循这种格式的效果，可能不如遵循模型插件编写的格式。
3. 声音检查为每个被引用的视频增加一次服务端检查。

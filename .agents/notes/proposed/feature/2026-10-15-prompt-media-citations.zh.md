# Agent Note: 提示词媒体引用

Status: proposed

[English](2026-10-15-prompt-media-citations.md) | 中文

## 问题

渲染调用接收一个 `prompt` 和一个单独的 `reference` 列表。提示词用 MiniMax H3 的标记指称每个参考，例如 `<Picture 1>`。这种设计有两个问题：

1. 这些标记只适用于一个模型。其他视频模型使用不同的写法。
2. 读提示词的人看不出每个标记指的是哪个媒体。

## 提案

渲染调用保留两个输入：参考列表和提示词。提示词用 harness 统一的写法引用参考列表中的条目。每个模型插件把引用换成它的模型的写法。现有的提示词和项目不需要迁移。

### 术语

- **参考列表**：渲染调用的 `reference` 输入，按输入顺序排列。模型插件把这些媒体发给模型。
- **引用**：提示词中指向一个项目条目的文字，写作 `@[<label>](dv:<kind>/<id>)`。
- **输入引用**：按角色引用渲染调用的一个输入，写作 `dv:input/<role>`，例如 `dv:input/first_frame`。它指向这个输入本身，不管输入的值是什么，所以也能指向某条记录还没产生的值。
- **元素**：项目中一组有名字、有版本的参考媒体。元素是 harness 提供给人和 agent 的概念。视频模型不知道元素。

### 归属

| 步骤                           | 归属                                                     |
| ------------------------------ | -------------------------------------------------------- |
| 定义引用格式并解析引用         | `@dv/project`                                            |
| 在界面中插入和显示引用         | `@dv/ui-composer` 和 `@dv/ui-canvas`，遵循 `@dv/project` |
| 按参考列表检查引用，并展开元素 | `@dv/shot-render`                                        |
| 声明参考上限，并转换引用写法   | 每个模型插件，例如 `@dv/fastvideo`                       |

`@dv/project` 负责引用格式，因为项目保存着引用所指的记录和历史。`@dv/models` 只是已注册模型的目录。

### 规则

1. 渲染调用接收一个参考列表和一个提示词。harness 按原样发送提示词，不改写它。
2. 提示词按素材引用参考列表中的条目，按角色引用调用的其他输入。如果一个引用指向不在参考列表中的素材，或指向调用没有的输入，那么渲染调用返回错误。
3. 参考列表中提示词没有引用的条目，照常发给模型。
4. 首帧是调用的 `first_frame` 输入，来自 `continue_from`，或来自设了 `continue_previous` 的分镜计划镜头。提示词以 `dv:input/first_frame` 引用首帧。分镜计划镜头只有在接上一镜头时才能引用首帧；否则 `plan.create` 和 `plan.update` 返回错误。
5. 元素的一个版本可以是参考列表中的条目。提示词以 `dv:character/<id>`、`dv:location/<id>` 或 `dv:style/<id>` 引用元素，不带版本，因为参考列表写明了版本。渲染时，harness 把元素展开成它的媒体，并把该元素的每个引用展开成这些媒体的引用。agent 和模型插件不展开元素。
6. 每个版本保存原始提示词和展开后的提示词。`shot.render` 的结果包含展开后的提示词。
7. 每个模型插件声明自己的参考上限，并把每个引用换成它的模型读取的标签。例如，MiniMax H3 把第 k 张参考图片读作 `<Picture k>`。
8. 模型插件可以加上它的模型自己的提示词规则。MiniMax H3 没有首帧槽，所以调用有首帧、但提示词没有引用它时，它的插件返回错误。

### 首帧

首帧打破了一个前提：写提示词时，被引用的条目已经存在，并且有素材 ID。首帧是调用的另一个输入。在分镜计划里，它是上一个镜头的最后一帧，agent 写计划时它还不存在。输入引用按角色指向输入，所以不需要输入的值。

多数视频模型在单独的槽里接收首帧，提示词不提它。MiniMax H3 只有一个媒体列表：只有提示词写明时，一张图才是首帧，例如 `[keyframe completion] … <Picture 2> is the first frame of [Shot 1]`（见官方指南第 2.2、3 和 5.3 节）。工作流工具用同样的办法解决同样的问题：一个步骤指向前一个步骤的输出，运行这个步骤时再填入值。

| 系统           | 首帧怎么进入请求                      | 提示词是否提到首帧           |
| -------------- | ------------------------------------- | ---------------------------- |
| MiniMax H3     | 在媒体列表中，排在参考图片之后        | 是，而且必须提到             |
| Seedance 2.0   | 每张图带一个角色，例如 `first_frame`  | 否；提示词文字设不了角色     |
| Google Veo 3.1 | 单独的 `image` 字段                   | 否                           |
| Kling          | 单独的 `image` 字段                   | 否                           |
| Luma           | `keyframes.frame0`                    | 否                           |
| Runway         | 带 `position: first` 的 `promptImage` | 否                           |
| GitHub Actions | 不适用                                | 一个步骤指向前一个步骤的输出 |

各种情况的做法如下：

- **直接渲染，接一个已完成的版本。** agent 传 `continue_from`，并写 `@[首帧](dv:input/first_frame) is the first frame of [Shot 1]`。运行器把输入解析成该版本的最后一帧。MiniMax H3 插件把引用换成参考图片之后的 `<Picture N>`。
- **分镜计划镜头，接一个还没渲染的镜头。** 提示词写同样的引用。`plan.approve` 加上 `first_frame` 输入；上一个镜头渲染完后，运行器解析这个输入。没有任何东西改写提示词。
- **有首帧槽的模型。** 它的插件把首帧放进槽。它的技能告诉 agent 不要引用首帧；引用了也只会换成引用的标签。
- **尾帧或关键帧。** 它是另一个输入，以 `dv:input/last_frame` 或 `dv:input/keyframe/2` 引用。

### 延后

在界面中提示“某个参考没有被提示词引用”，等收集用户反馈后再决定。

### 交付

- 每个 PR（Pull Request）只依赖已经合并的 PR。基础 PR 合并之后，再开下一个 PR。
- 每个 PR 在测试之外最多改动约 300 行。
- 每次合并之后，`main` 都能正常工作。

PR 按以下顺序提交：

1. 本 Agent Note。
2. `@dv/project` 中的引用解析器，以及 `@dv/fastvideo` 中到 `<Picture N>` 的转换。没有引用的提示词照常渲染。
3. `shot.render` 按参考列表检查引用，并更新工具描述和技能。
4. 版本编辑器和分镜计划视图中的引用缩略图。
5. 首帧引用 `dv:input/first_frame`，以及分镜计划检查和 MiniMax H3 的提示词规则。
6. 元素引用及其展开。
7. 视频引用。
8. 音频引用。

## 考虑过的替代方案

**只从提示词读出参考列表。** 用户可以在提示词里输入任何文字，纯文本提示词不引用任何东西。单独的参考列表能保留用户添加的每个参考，也符合视频模型的请求格式：一个媒体列表，加上指称这些媒体的提示词。

**按值引用首帧。** 提示词以 `dv:record/<record>#1` 引用最后一帧。分镜计划镜头引用不了还不存在的记录，所以计划需要自己的写法，由 `plan.approve` 改写，同一张图会有两种写法。

**只为首帧设一个占位写法（`dv:first-frame`）。** 它能用，但以后每个输入（尾帧、关键帧）都要各自的占位写法。按角色的输入引用用一种写法覆盖所有输入。

**提示词中使用模型标记。** 每个视频模型的写法都不同。参考顺序变化时，按位置编号的标记也会改变编号。

**只能引用元素中的单个媒体。** 用户每次都必须逐个选择媒体。为参考媒体分组的视频产品会为整组插入一个引用。

**由 agent 展开元素。** agent 必须查出每个元素的媒体，提示词也会丢失分组。

**由每个模型插件展开元素。** 每个插件都必须了解元素，而且每个插件都重复同样的代码。

**丢弃超过上限的媒体。** harness 会悄悄删掉媒体，替 agent 或用户做决定。

## 验收标准

1. 提示词引用了参考列表之外素材的渲染调用会返回错误，并且不渲染。
2. 对于引用参考列表中一张图片的提示词，`@dv/fastvideo` 发送 `<Picture 1>` 和那张图片。
3. 元素引用展开成该元素版本的媒体，版本同时保存两个提示词。

## 风险

1. 展开后元素的文字由 harness 决定。模型对这段文字的理解，可能不如由它的插件写出的文字。
2. 在输入的值存在之前，界面上的输入引用没有缩略图。
3. agent 要遵守每个模型关于是否引用首帧的规则。MiniMax H3 的检查为 MiniMax H3 执行这条规则。

# Maintain the Reactor provider

English | [中文](reactor.zh.md)

Use this guide to update `@dv/reactor` when Reactor adds a model, changes a workflow, or publishes a new SDK. For host setup and configuration, see the [Reactor plugin README](../../../packages/dv/reactor/README.md).

## Change a model or protocol

1. Compare the deployed model's schema with the existing profiles. For a compatible private deployment, configure its native ID and reuse the profile. For a new workflow, add the model's supported tasks, durations, output sizes, and input limits to [profiles.ts](../../../packages/dv/reactor/src/profiles.ts). [Reactor model API reference](https://docs.reactor.inc/model-api-reference/overview)
2. Use Reactor's [Clip Generation API](https://docs.reactor.inc/generations/api-reference) for a model whose API reference has a "Generate a clip" section. Set `workflow: { kind: 'generation', ... }` in [profiles.ts](../../../packages/dv/reactor/src/profiles.ts) with that model's input names for the first and last frame, and keep the HTTP calls in [generations.ts](../../../packages/dv/reactor/src/generations.ts). Models without that section use [the SDK bridge](../../../packages/dv/reactor/src/render.py), which keeps Reactor-specific commands, events, and recording behavior. Streamed workflows capture a clip from the session. PixVerse downloads a saved step. Do not capture a queued clip from a session recording: a recording becomes ready only while the session keeps generating. Update the SDK version in the [host setup](../../../packages/dv/reactor/README.md#use-this-package) when you verify a version change. [Reactor Python SDK](https://docs.reactor.inc/sdk-reference/python/reactor) · [Reactor recordings](https://docs.reactor.inc/concepts/recordings)
3. Resolve `REACTOR_API_KEY` through the host credential service. Catalog discovery requires a key, opens no generation session, and uses the `catalogTimeoutSeconds` deadline. `apiBaseUrl` selects the Reactor API origin for the catalog, Clip Generation requests, saved-step downloads, and the SDK session. `timeoutSeconds` bounds a Clip Generation render (upload, generation, and download) or an SDK session, and each registered duration must be shorter than `timeoutSeconds`. `pollIntervalMs` sets the Clip Generation poll interval. A Clip Generation request is submitted once and never retried, because a lost response may hide a started paid generation. Cancelling or reaching the deadline sends `DELETE /sessions/{generation id}` once Reactor has accepted the generation, and cancelling an SDK render requests an SDK disconnect. The server-side session limit covers a lost connection during SDK cleanup. The Clip Generation reference does not state how Reactor bills a generation, so confirm billing with Reactor when you add a model.

## Verify and submit

Run the provider and bundle tests with `ffmpeg` and `ffprobe` available. The [fake Clip Generation API](../../../packages/dv/reactor/tests/fake-reactor-api.ts) covers uploads, submission, polling, download, errors, deadline, and cancellation, and the SDK fixture covers the streamed models, PixVerse, and their cancellation. Both feed model registration and media import in the bundle tests. [Catalog tests](../../../packages/dv/reactor/tests/catalog.spec.ts) · [Bundle tests](../../../packages/bundle/dv/tests/reactor.spec.ts)

For a paid live smoke, use an approved test credential and the interpreter with the pinned SDK. The [live test](../../../packages/bundle/dv/tests/reactor-live.e2e.ts) opts in with `DV_REACTOR_LIVE_TEST=1` and uses `REACTOR_API_KEY`. FastH3-Omni runs over the Clip Generation API, so the interpreter is needed only to test an SDK model. Verify the changed model and task, and include the model ID, SDK version, test result, and any affected limits or session behavior in the PR. [Contribution guide](../../../CONTRIBUTING.md)
